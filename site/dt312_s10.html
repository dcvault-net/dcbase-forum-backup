NattensQje wrote:
Negedrazzil wrote:I noticed that DC++ .22 has that handy new feature that reports when someone search spams the hub.

Is it new?

No, it is not new. It's been in the program for quite a while (since 0.163 I *think* - but I'm not 100% sure).

In my new betas of DC++k I've added the ability for the user to specify how often (in milliseconds) the program is allowed to search. I've retrofitted the search window and the autosearch to follow and understand this limit. It is then up to the user to choose a suitable period of time. I think that this way everyone gets what they want, but you could make a special case, such as setting the limit to -1 and thus defaulting the period to, say, five seconds for an active user and ten seconds for a passive one. The numbers I've chosen are completely from the top of my head, of course.

Post by sarf » 2003-02-16 21:35

splunger wrote:Can anyone explain how the "Automatically search for alternative download locations" functionality works? For example, does it go through the download list and the search through the hubs you are on? Is the a priority to the searches?

"Auto search for more sources" (my name) works by going through your filelist a bit at a time and searching for a file once every minute (I think). It keeps a list of 30 (last time I checked) searches in its "memory". When one or more new sources are found the file is removed from the search list.

Every search - no matter what type of search it is - is broadcasted to every hub.

When you press the "Search"-button in the Search window DC++ sends a search command to all hubs that it is connected to at that moment. AFAIK, it does not send any more searches to the hub unless you resend the search command.

splunger wrote:I think if a search is done and left running it will overlap an Auto Search.

Wrong. What may happen is that if you are unlucky, your "auto search" will kick in just before or after you have sent another search. This is rather unlikely but it is possible.

splunger wrote:Are manual searches that are left to run, only run once per hub?

Yes.

splunger wrote:What if new hubs are joined during a search? Do those hubs get searched subsequently?

Nope. All hubs that the DC++ client is connected to at the moment the search method is invoked are sent a search-command.

splunger wrote:I find that manual searches get me results and I'd like to understand how it and Auto Search work together better.

Well, I hope this has given you a slight idea of what is happening "behind the scenes".
