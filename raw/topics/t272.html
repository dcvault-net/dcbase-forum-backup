Post by en_dator » 15 Aug 2008, 09:03

I think I understand why you would want all emu's into one, but I think that it would cause more issues than it solves, like for example what IS an emulation client?

as I see it you have a couple of options
1) one emu for each client as it was in aml 3 (this I like as it means I can decide which clients I want in the hub, but ofc it means more work to maintain, and more detections in the list. But it has also another advantage - compare #3)

2) one emu for all (this I do not like)

3) a small number of emu definitions, for example one "good", one "bad".
Downside is that no matter how the clients are divided there will always
be much 'discussion' about where a client belongs.

4) Put the standard and emu mode of the client into the same definition
(this I would prefer, but I dont know if its possible)

the last option is what I would prefer, if that cant be done, i'd like
the first one.

There - thats what I think about it
