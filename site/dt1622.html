Adding of all search hits as alternative download locations

Post by JCTor » 2003-03-23 17:50

I have activated the feature "Automatically search for alternative download locations" in my DC++ (0.24).

Right now, when I issue a search that generates hits for any of the files that are in my download queue, only some of them are added as alternative sources in the download queue, and this adding is seemingly arbitrary?!

For example, if I have the following files in my download queue:

someapp_01.zip
someapp_02.zip
someapp_03.zip
someapp_04.zip
someapp_05.zip
someapp_06.zip

And then I issue a search for for example "someapp_0". Let's say I then find 5 people in the search that have all these files (and they show up in the search result window too, so it's not due to the limiting of search hits from individual users).

Then I would like that _all_ these users should automatically be added as alternative sources for _all_ these files. Right now they only seem to be added to one file per user at the time, and then I have to issue the same search again and again (when the current download from these users are complete) to make it start downloading another file from these users again.

I think this is highly inefficient, and I cannot understand why it is like this? Wouldn't it be great to make it so that all hits in a manual search that are already in the download queue are added as alternative sources? It would be such an efficiency improvement, don't you agree?

Did you do a manual "Search For Alternates", or a regular search? There's a bug report (in the tracker on sourceforge, down at the moment), I believe, that says that searching for certain substrings of a file doesn't always return that file.
