Can you be more specific than "doesn't work"? How does it fail? What error messages show up in the Download Queue's Error column?

Edit:
mesca wrote:i use antifragmentation method and the exact file size are the same in boths.

If you use the antigragmentation method, you either have to download the files from scratch, or use a hex editor and chop off the (presumably zero-filled) data that hasn't been downloaded yet. Not everyone is going to be able to do this, that's why there are some warnings about using the antifragmentation download option. From the help file:
The drawbacks are a short pause at the start of every download during which the drive space is reserved, less drive space being available while you are downloading, and possibly losing progress on your download if Windows crashes and DC++ cannot exit cleanly.

Post by joakim_tosteberg » 2005-10-15 15:56

He just told you that. By having the anti-fragmentation feature enabled DC++ won't be able to resume the file as it need to know how much you have downloaded t obe able to resume correctly. You have some options 1. use some hex editor and try to locate where the download did stop, as Gargoyle said everything after where the download stopped will probably just be zeroes. If you manage to do that you can eighter try to chop of the file at that point and try to resume it (I think you would have to remove the .antifrag extensions from the files too) or you could edit queue.xml setting downloaded=X to the correct value.
Or you could just restart the downlaods fro mthe beginning.
