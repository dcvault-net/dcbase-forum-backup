Feature requests: download queue stuff

Post by Nazo » 2003-04-07 04:27

First of all, it's very useful the way one can set download priorities. However, since often I end up having to queue up a large number of files that I want to get as in order as is possible, it would be very nice if there were a larger number of priority settings. It occured to me that you could just simply have a number system. I first thought you might have something like a selection bar that sets 1-100, but now I think it might be easiest of all to just have a text box where the user can enter any valid number. I think it looks like this would be a pretty minimal and easy change to DC++ so I hope you will consider it.

Another idea I had is that it would be nice if there were some sort of way you could tell it that if it successfully gets one file, then it shouldn't get another file or files. This comes in handy when one has to pick multiple sources that have multiple versions of the same thing (happens rather often with video files especially.) If it finishes one copy, then it shouldn't waste space, bandwidth, download slots, and time on the other (not to mention that one might have the next one in the series queued after that from the same source, so they wouldn't get the next one until they either manually removed the download or the unnecessary file finished. I hope you will consider this one as I run into this problem all the time.

Post by Nazo » 2003-04-15 10:45

Yeah, the higher priority level thing would handle that somewhat, but, to begin with, it could maybe pick which one to get in which order by a little bit of just looking at teh filename. Such as for file01.ext, file02.ext, and file03.ext, regardless of their size, it seems likely that of those files that all fit the criteria file0?.ext, the proper order to get them is likely 1,2,3. Of course, this wouldn't be 100% perfect since there tend to be many different filenames for the same things sometimes. This would be especially handy since the primary things I'm downloading do come in series, but I suppose it wouldn't help me much since I'm having to just download as much as 5 different filenames of the same single part sometimes. Anyway, being able to adjust priorities more should probably do since it would at least let you manually do that.

It occured to me that cancelling might not be such a great idea necessarily sometimes. Every now and then I get something that doesnt' work right (just last night even) and have to get another source of it. Rather than having to track down a source for the same file(s) that I already have part of, it would be easier if the automatic thing merely paused instead of cancelling so that I can remove the sources from the download queue or unpause at my leisure. I suppose if it used any valid integer or whatever then 0 would be paused.

BTW, I suppose it's been proposed before, but I think what we really need is some kind of scripting system kind of like the way mIRC does. I can't even begin to comprehend the kind of work it would take for that (though I know it's mindnumbingly painful amounts) but I think that if such a system were to be created, it would be just absolutely wonderful for the DC community. Many of the ideas that people request, likely even mind, could likely be handled with just a little scripting if it were done right. For example, in mIRC I wanted joins/parts out of the chat, but still visible easily, so I moved all of them into a seperate small window I made just for them all with a script that could be reduced to a single line without too much removal of white space. The idea is simple, but it would still be a bit of a pain to implement by coding it into the application itself, however a script can potentially do it with ease. This, of course, all depends on the nature of whatever scripting language you came up with and how exactly it worked with the client.

I'm sure that idea has been mentioned before, but, just in case I wanted to add it.
